## NIP-05 — DNS identifiers
Source: 05.md · Status: `final` `optional`
- Kind-0 `nip05` field; GET `https://<domain>/.well-known/nostr.json?name=<local-part>`; `names` map + optional `relays` map.
- Identification, NOT verification — clients follow pubkeys, never NIP-05 addresses.
- Endpoint MUST NOT redirect; fetchers MUST ignore redirects; keys lowercase hex; `_@domain` = root.
- Can advertise NIP-46 signer endpoints (`nip46` object).
- Operational security (swarm guidance, ADR-0004): NIP-05 binding inherits DNS/web PKI risk — domain-expiry hijack, registrar compromise, and TLS CA compromise can silently re-bind name→pubkey. Mitigations: monitor your own `/.well-known/nostr.json` for unexpected changes; clients should flag pubkey changes behind a previously seen identifier; flows that DISPLAY NIP-05 names (zaps, profiles) must treat them as hints, not identity proof.

## NIP-09 — Event Deletion Request
Source: 09.md · Status: `draft` `optional` `relay`
- Kind **5** with `e`/`a` tags (SHOULD include `k` tags); relays SHOULD delete matching-pubkey events; clients MUST validate pubkey equality themselves (relays not authoritative).
- `a` tag deletes all versions up to deletion's `created_at`. No undelete. Deletion events republished indefinitely.

## NIP-11 — Relay Information Document
Source: 11.md · Status: `draft` `optional` `relay`
- HTTP at relay URI with `Accept: application/nostr+json`; all fields optional; unknown fields ignored; CORS required.
- Fields: name, description, banner, icon, pubkey, self, contact, supported_nips, software, version, terms_of_service.
- `limitation`: max_message_length, max_subscriptions, max_limit, max_subid_length, max_event_tags, max_content_length, min_pow_difficulty, auth_required, payment_required, restricted_writes, created_at bounds, default_limit. Paid relays: payments_url, fees.

## NIP-19 — bech32 entities
Source: 19.md · Status: `draft` `optional`
- Bare: `npub`, `nsec`, `note`. TLV: `nprofile`, `nevent`, `naddr` (nrelay deprecated). TLV types: 0 special, 1 relay (repeatable), 2 author, 3 kind.
- Unknown TLV types ignored; ≤5000 chars; `npub` MUST NOT appear inside NIP-01 events or NIP-05 responses; bech32 for display/sharing only.

## NIP-51 — Lists
Source: 51.md · Status: `draft` `optional`
- Public items in `tags`; private items = JSON tag-array NIP-44-encrypted to own key in `.content` (legacy NIP-04 detectable via "iv"; deprecated).
- Standard lists: kinds 3, 10000–10102 (mute, pin, relay list, bookmarks, communities, blocked/search relays, badges, groups, interests, emojis, DM relays 10050, Blossom servers 10063…).
- Sets: addressable 30000–39092 with distinct `d`; optional title/image/description. Append chronologically.

## NIP-57 — Lightning Zaps
Source: 57.md · Status: `draft` `optional`
- Kind **9734** zap request NOT published to relays — sent via LNURL callback as `nostr` param; tags: relays, amount (msats), lnurl, p, optional e/a/k.
- LNURL server must advertise `allowsNostr: true` + `nostrPubkey`; invoice description hash commits to zap request JSON.
- Kind **9735** receipt: p, P (sender), e/a, bolt11, description (zap request JSON), optional preimage.
- ⚠ Receipts are NOT proof of payment: clients MUST validate receipt pubkey == LNURL nostrPubkey and bolt11 amount == request amount.
- `zap` tags = weighted splits.
